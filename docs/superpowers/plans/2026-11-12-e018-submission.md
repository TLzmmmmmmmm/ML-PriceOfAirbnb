# E018 CatBoost Submission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train the approved diagnostic E018 CatBoost model on every training row and produce one validated local Kaggle submission without uploading it.

**Architecture:** Reuse E018's tested feature frame and fixed CatBoost parameters, set iterations to the median outer-CV best iteration (`1817`), and fit without an evaluation holdout so all 33,538 rows contribute. Pass predictions through the existing submission creation and validation functions.

**Tech Stack:** Python 3.12, CatBoost 1.2.10, pandas, NumPy, scikit-learn, pytest, joblib

**Spec:** User-confirmed E018 submission request in the 2026-11-12 conversation; project-wide rules are in `CHALLENGE_PLAN.md`.

## Global Constraints

- Run with the approved CatBoost virtual environment.
- Use the same 142-source-feature configuration as E018.
- Fix the full-data model at 1,817 iterations and do not tune from Kaggle results.
- Use all training rows; do not create an early-stopping holdout.
- Generate exactly `Id` and `Predicted` in test order.
- Do not upload the CSV or alter selected Kaggle submissions.
- Keep the full model and CSV out of Git.

## Review Focus

- Full training must not silently change E018's feature set or parameters.
- The 1,817 iteration choice must match the median of recorded CV best iterations.
- Predictions must align with test IDs and contain only finite nonnegative values after the existing submission policy.
- Aggregate hashes and statistics must match the generated artifacts.
- The experiment remains documented as diagnostic because E018 failed its direct-replacement gate.
